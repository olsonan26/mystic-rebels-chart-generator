# First personalized interpretation: internal review lane

This is an offline review tool, not a customer feature or a new architecture.
It reuses `generate_report`, the unchanged integrity-verified private0.7.0 core,
`function_components`, `context_graph`, `compose`, motion evidence and
`validate_composition`. It does not activate any new core rule or release.

The smallest added operation binds the existing safety function to one of two
already inspected occupied-Field meanings using the source's ordered thematic
grammar. It verifies the participant against recomputed calculated components
before proposing a theme. This is a bounded interpretive step, not a complete
personal conclusion or an equal-factor score.

The natural-language candidate is a controlled hypothesis, not evidence that
the software has learned complete contextual reasoning. Its recognition,
explanation and conditional practical adaptation remain explicitly unapproved.
Full related-condition return, question-specific priority and personal-context
adjudication remain separate. Source citations alone do not certify entailment.

## Run with private input, locally

```text
python scripts/personal_review.py --input /private/local/report.json --output tmp/first-personal
```

The input is an existing profile JSON (its `chart.input` is recalculated) or a
BirthInput record. Output is restricted to the ignored consumer `tmp` tree.
The script produces the target draft plus three explicitly synthetic charts,
the complete calculation/claim/context records, HTML review drafts and a
comparison. It makes no network or inference API calls. Missing Field vocabulary
withholds a candidate rather than substituting generic personality prose.

Private birth details, observations, hypotheses, source-bearing prompts, model
outputs and PDFs must not be committed or uploaded without explicit owner
authorization. The current task provides no such upload authorization.

## Evaluation and gates

- Correct calculated binding, source applicability, actual contextual
  contribution and a complete answer are independent requirements.
- Compare configurations, their proposed meaning, and known unsupported
  transitions. Different wording alone is not successful personalization.
- Distinguish source statements, bounded combinations, interpretive hypotheses,
  new practical adaptations and explicitly rejected statements.
- Review every claim and every participant contribution, not only a model's
  short list of claims. A fluent summary cannot hide an incorrect placement,
  invented contact or unsupported semantic transformation.
- Keep reported experience distinct from chart evidence, retain the observer's
  identity and uncertainty, and preserve proposals made before that context.
- An optional local-model composition is an internal proposal only. Preserve
  prompts, exact settings, failures and source-packet corrections locally; do
  not feed the expected hypothesis or evaluation references to the model.

No customer route, approval switch or writer egress is added. The null personal
answer and `personal_readings_approved=false` remain effective. No model may
approve its own draft. Neither the core's recomputation validator nor these
tests proves unrestricted prose entailment or empirical accuracy.
