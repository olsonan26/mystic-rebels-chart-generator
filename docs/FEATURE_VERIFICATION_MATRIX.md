## Runtime unavailable states that must remain explicit

- Unknown birth time deliberately uses local noon as a reference and suppresses angles, houses and dependent Parts. This is missing user input, not an engine failure or an invitation to assign a house.
- Missing/corrupt ephemeris assets, unsupported object IDs and installed-file date limits report typed errors. Core1800-2399 and additional-body1800-2099 limits remain separate.
- Singular horizon geometry cannot acquire a fabricated Ascendant, Vertex or derived house. Existing geometric and unknown-time tests remain in place.
- Gradity's bounded event search can lack a complete surrounding cycle near the file limits; this returns unavailable instead of assuming Prograde. Asteroid Gradity remains outside the independently checked event implementation.
- Successive outer-planet shadow intervals can overlap. When the source supplies no precedence between simultaneous Pregrade and Postgrade memberships, retain the event evidence and report an unresolved phase. A convenient choice of the nearest loop is not source verification.

## Verification scope and regressions

The new event solver changes derived Gradity metadata, not astronomical positions or established placement formulas. `scripts/methodology_regression.py` checks immutable pre-change outputs; the original wheel, numerical and independent-astronomy fixtures remain retained. Frontend regression tests cover scoped server phases, old charts with no events, null boundaries, unavailable searches, non-applicable mathematical points, untouched input records, source citations and lossless event details. The complete build and astronomy/access test results are recorded by the release run.

`VERIFIED_FOR_SUPPORTED_PLANETS` means the documented event-to-phase method has been implemented for that supported set, with independent astronomical sampling described in `astronomy-followup.md`. The numerical root bracket, reference residual, birth-time uncertainty and scientific evidence for an interpretation are separate quantities. The UI's Method verification disclosure exposes the API's scope rather than presenting a blanket Verified claim.

Focused Logan questions, including exact conflicting cases and missing original pages, are listed in `METHODOLOGY_SOURCE_REVIEW.md`. Their dependent rules remain blocked while unaffected calculations continue working.
